# Contribution and release safeguards

Use feature branches from current main and Draft PRs. Include the candidate SHA, source inputs, test commands/results, visual review and unresolved limitations. Keep private research, credentials, workstation paths, agent instructions, corporate documents, asset masters and raw recordings outside the public repository. Maintain original asset attribution and third-party licenses.

CI verifies the static build, browser journeys and accessibility. Passing CI is not creative acceptance or authorization to merge or deploy. A non-author review and owner authorization remain required. Production deployment and DNS changes are separately authorized operations. Vercel preview must remain noindex. Hostinger production serves only the reviewed build output, never the repository root.
